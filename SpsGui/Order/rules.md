# Spsの目的

このプロジェクトの目的はSteamP2PInfoを改良した新しいSteam P2P パケットのアナライザーを作成することです
以下の目的があります
1. 
SteamP2PInfoのping計測方法は
TraceEventSession.EnableKernelProvider(KernelTraceEventParser.Keywords.NetworkTCPIP);
によりUDPパケットの送受信をモニタリングし、パケットはその概要しか調べられないため、pingみたいな挙動を取る。
classicstunパケットをそのサイズから推測して、その送受信タイミングから計算する方法になりますよって、相当pingが高くて過去のstunパケットの返信が最新の送信パケットの直後に来られてしまうと、低pingとして認識されてしまう。
よって、これを解決することが課題になり、実際にstunパケットを取得しtransaction idからペアを確実に入手する必要がある。
これにより、低ピング問題を解決したり、もしくはパケロスを検知することも出来るようになります。
使用するライブラリは[https://github.com/dotpcap/packetnet/tree/master](https://github.com/dotpcap/packetnet/tree/master)を想定しています。
2. p2pだけでなく、安定したサーバーとのやり取りとのpingを計測し、自分の環境に問題があるかの確認を行う。p2pだとその人に問題があるか自分に問題があるかが区別できないので、安定したサーバーとのping確認も常にやってユーザーが比較できる状況を整えることが重要。pingを気軽に行える無料のサーバーをどう確保するかが重要になり、恐らくAWSが提供しているかもしれません。ここはしっかり調べてください。
3. パケットのログを出力する。実際のp2p通信が良かった/悪かったことの証拠として、ログを出力するのが最も効果的。直近試合のパケットのログを自動で保存する機能を作成したいところ。(P2Pなので、相手のIPとの通信のみをログに残す形になります)

# UI設計のルール

MetroUIをライブラリとして使用可能です。
App.xamlのResourceDictionaryにてMetroUIの各コンポーネントのデザイン設定を適応しています。
通常のUIの代わりに、極力MetroUIを使用してください。
https://mahapps.com/docs/guides/quick-start
に始まるサイトで使用方法が書かれています。
各UIコンポーネントを極力これに依存するように設計し、デザインの統一化を計ってください。
SteamP2PInfoはかなりよい参考元になるでしょう。
なお、過剰な表現は避け、シンプルでわかりやすいUIを心がけてください。
特に、オーバーレイはグラフ表示はしても問題ありませんが、他はテキストに留め、過剰な表現になってしまわないようにしてください。
